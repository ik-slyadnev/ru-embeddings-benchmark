## ❓ Вопросы

Вопросы лежат в папке [data](data), по три файла на язык.

| Файл | Вопросов | Что в них |
|---|:-:|---|
| `queries.jsonl` | 2000 | обычные вопросы о том, как работает код; классы и методы называть нельзя, комментарии копировать тоже |
| `queries_names.jsonl` | 204 | в вопросе прямо назван класс или метод |
| `queries_usage.jsonl` | 250 | «где используется X», правильных ответов несколько |

Обычные вопросы делятся на пять типов.

| Тип | О чём спрашивают | Вопросов | Пример |
|---|---|:-:|---|
| ⚙️ `behavior` | как работает код | 747 | Откуда команда берёт новый мастер-ключ для ротации и как генерируется случайное значение секрета длиной 256 бит? |
| 🔀 `condition` | что происходит при условии | 458 | Почему при сборке составного описания типов в упорядоченный набор не попадает тип значения «Неопределено»? |
| 📍 `location` | где это реализовано | 341 | В какой таблице переменные шага за одну итерацию цикла сохраняются одним JSON-столбцом с привязкой к отчёту? |
| 🗂 `data` | какие поля и параметры | 274 | Какие порядок байтов и разделитель строк получает по умолчанию объект записи двоичных данных в файл или поток? |
| 💡 `rationale` | зачем сделано именно так | 180 | Почему часовой пояс сессии PostgreSQL задаётся POSIX-строкой с перевёрнутым знаком, а не смещением вида «+03:00»? |

Пример вопроса с именем: *«Какой псевдоним предлагает K8sCheckConfig.offerAlias, если он не задан явно?»*

> [!NOTE]
> Обычные вопросы и вопросы с именами написал Claude по куску кода, к которому задан вопрос; слабые вопросы
> отброшены. Вопросы «где используется» собраны автоматически по идентификаторам, у которых от 2 до 10 мест
> использования.

Каждая строка файла это один вопрос. Правильный ответ указан файлом и строками на коммите из таблицы проектов,
путь считается от указанной там части репозитория.

```json
{"query_id": 0, "type": "behavior",
 "query": "Как русские синонимы операций вроде «провести» или «удалить» приводятся к каноническому виду при проверке матрицы прав роли?",
 "answers": [{"file": "auth/role_check.go", "start_line": 1, "end_line": 57}]}
```

| Поле | Что значит |
|---|---|
| `query_id` | номер вопроса внутри языка |
| `query` | текст вопроса |
| `type` | тип вопроса из таблицы выше; у вопросов «где используется» это `usage_function` и похожие |
| `answers` | правильные куски кода: файл, первая и последняя строка |
| `identifier`, `definition` | только у вопросов «где используется»: сам идентификатор и место, где он объявлен; объявление правильным ответом не считается |

## ⚙️ Как мерили

| Шаг | Что делаем |
|:-:|---|
| ✂️ Нарезка | Каждый файл режется на куски по синтаксису: один кусок это один класс, метод или функция. Кусок длиннее 2000 символов режется на окна по 1500 символов, соседние окна перекрываются на 300. В начало окна дописывается строка вида `// Context: RollupOptions \| // Location: rollup.go (Layer: OTHER)`. |
| 🔤 Префиксы | Модели получают префиксы из своих карточек (например, `query:` или `search_document:`). Моделям с инструкцией к запросу даётся одна и та же инструкция о поиске кода по вопросу о кодовой базе. |
| 🔎 Поиск | Модель превращает в вектор каждое окно и вопрос, поиск идёт точным сравнением векторов по всем окнам проекта, кусок получает оценку своего лучшего окна. |
| 🖥 Запуск | Локально на Mac Studio (Apple M4 Max, 64 ГБ) через sentence-transformers или Ollama. |
| 📊 Усреднение | Метрики считаются внутри каждого языка и потом усредняются, так что каждый язык весит одинаково. Группы вопросов тоже считаются внутри языка, иначе разница между проектами выдавала бы себя за разницу между группами. |
| 🎲 Статистика | Доверительные интервалы получены бутстрепом внутри языка, отставание от лидера проверено парным перестановочным тестом с поправкой Холма на число сравнений. |

| Метрика | Что показывает |
|---|---|
| **MRR@10** | главная метрика: 1.0 значит, что правильный кусок всегда первый, 0.5 значит, что в среднем второй, 0 значит, что его нет в первой десятке |
| Recall@1, @5, @10, @30 | доля вопросов, где правильный кусок попал в первые 1, 5, 10 или 30 результатов |
| nDCG@10 | похожа на MRR@10, но учитывает и остальные правильные куски ниже первого |
| R@30 в контексте LLM | попал ли правильный кусок в те 30 кусков, которые RAG передаёт языковой модели: из 160 лучших окон собираются 80 кусков, с одного файла берётся не больше 2–4 |

## ⚠️ Ограничения

| Ограничение | Что это значит для читателя |
|---|---|
| Вопросы синтетические | На живых вопросах цифры будут ниже, сравнивать стоит модели между собой |
| Один проект на язык | Разница между языками это ещё и разница между проектами |
| В TypeScript 20 вопросов с именами | Выводы по этой группе внутри одного языка ненадёжны |
| Вопросы «где используется» сделаны по шаблонам | Живые формулировки разнообразнее |
| Вопросы составлял и разметку проверял Claude | Модели этого семейства в рейтинге не участвуют, но влияние автора вопросов полностью исключить нельзя |
