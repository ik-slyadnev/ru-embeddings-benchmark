# Какая embedding-модель лучше ищет код по вопросам на русском

Я хотел понять, какую открытую embedding-модель брать для RAG по коду, если вопросы задают на русском.

Вопросы на русском. Код и имена в нём на английском, комментарии и на русском, и на английском. Модель должна найти
в проекте chunk, который отвечает на вопрос.

|:-:|:-:|:-:|:-:|:-:|
| **63** и BM25 | **5** | **5** | **2454** | Mac Studio, M4 Max, 64 ГБ |

>

Модели с пометкой *(Ollama)* я запускал через Ollama, остальные через sentence-transformers. BM25 это не нейросеть, а
обычный full-text search по совпадению слов. Он нужен как точка отсчёта. Знаком ⚠️ отмечены лицензии, которые запрещают
коммерческое использование.

> **Главное**
>
> Giga-Embeddings-instruct-3B и Giga-Embeddings-instruct-10B статистически неотличимы друг от друга. Все остальные
> модели отстают от них значимо.
>
> Места с 3-го по 8-е занимают сборки Qwen3-Embedding 4B и 8B в разной квантизации. Разница между ними до 0.014,
> это почти шум.

> **Вопросы «где используется»**
>
> На вопросах «где используется» слабы все модели. Правильных ответов там несколько, и похожи они друг на друга
> только именем.
>
> Тут помогает не другая модель, а hybrid search. Если смешать выдачу vector search с full-text search (BM25), MRR@10
> поднимается до 0.61–0.65 у всех четырёх моделей, которые я проверил.

## В чём именно какая модель лучше

Я разделил обычные вопросы на группы по смыслу и по тому, какой код за ними стоит. Потом посмотрел, кто лидирует в
каждой группе.

В скобках MRR@10. Giga-3B и Giga-10B это Giga-Embeddings-instruct-3B и -10B.

| Группа вопросов | 1-е место | 2-е место |
|---|---|---|
| Как работает какой-то код | Giga-3B (0.868) | Giga-10B (0.865) |
| Что происходит при определённом условии | Giga-3B (0.801) | Giga-10B (0.779) |
| Какие есть поля и параметры | Giga-10B (0.863) | Giga-3B (0.855) |
| Где это реализовано | Giga-10B (0.887) | Giga-3B (0.872) |
| Зачем сделано именно так | Giga-3B (0.868) | pplx-embed-v2-late-0.6b (0.855) |
| В вопросе назван класс или метод | Giga-3B (0.880) | Giga-10B (0.869) |
| Где используется класс или метод | bge-code-v1 (0.503) | Qwen3-Embedding-4B q4 (0.450) |
| В нужном коде только английские комментарии | Giga-3B (0.843) | Giga-10B (0.816) |
| В нужном коде есть русские комментарии | Giga-3B (0.852) | Giga-10B (0.850) |
| В проекте есть почти копия нужного кода | F2LLM-v2-4B (0.805) | Giga-3B (0.788) |

Остальные места и все модели по каждой группе есть в [подробном отчёте](results/report.md).

## Как я мерил

Я взял пять открытых проектов, по одному на язык.

| Язык | Проект | Что это |
|---|---|---|
| Java | [SyTester](https://gitverse.ru/sbertech/sytester) | инструмент тестирования от СберТеха |
| Python | [giga_agent](https://gitverse.ru/GigaTeam/giga_agent) | бэкенд ИИ-агента на GigaChat |
| Go | [onebase](https://github.com/ivanarama/onebase) | бизнес-платформа для учётных задач |
| C# | [OneScript](https://github.com/EvilBeaver/OneScript) | среда исполнения скриптового языка 1С |
| TypeScript | [ui-kit-ce](https://gitverse.ru/sbertech/ui-kit-ce) | библиотека UI-компонентов от СберТеха |

Дальше всё шло в пять шагов.

| Шаг | Что я делал |
|:-:|---|
| 1 | Разрезал каждый файл на chunks по синтаксису: один chunk это один класс, метод или функция. Chunk длиннее 2000 символов разрезал на windows по 1500 символов с перекрытием 300. |
| 2 | Составил вопросы: 2000 обычных, где нельзя называть классы и методы, 204 с именами и 250 «где используется». |
| 3 | Каждой моделью превратил в векторы все windows проекта и вопрос, нашёл ближайшие windows. Chunk получает оценку своего лучшего window. |
| 4 | Посчитал метрики внутри каждого языка, усреднил и проверил, значима ли разница между моделями. |
| 5 | Попросил Claude вслепую перепроверить 1038 спорных вопросов. Исходная разметка подтвердилась в 98% случаев, места лидеров не поменялись. |
