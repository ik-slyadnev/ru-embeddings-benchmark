# 🔎 Какая embedding-модель лучше ищет код по вопросам на русском

Разработчик спрашивает по-русски, а модель должна найти в проекте кусок кода, который отвечает на вопрос. Код и
имена в нём английские, комментарии бывают и русские, и английские. Ровно так работает RAG по коду, когда вопросы
задают на русском, и здесь мы проверили, какая открытая модель справляется с этим лучше.

> 🥇 **Giga-Embeddings-instruct-3B** и 🥈 **Giga-Embeddings-instruct-10B** статистически неотличимы друг от друга,
> все остальные модели отстают от них значимо. Места с 3-го по 8-е занимают сборки Qwen3-Embedding 4B и 8B в

> [!IMPORTANT]
> На вопросах 🔗 «где используется» все модели слабые: правильных ответов там несколько, и похожи они друг на друга
> только именем. Помогает не другая модель, а гибридный поиск. Если смешать векторную выдачу с поиском по словам
> (BM25), MRR@10 поднимается до 0.61–0.65 у всех проверенных моделей.

Модели с пометкой *(Ollama)* запускались через Ollama, остальные через sentence-transformers. BM25 не нейросеть, а
обычный поиск по совпадению слов, он нужен как точка отсчёта. ⚠️ отмечены лицензии, которые запрещают коммерческое
использование.

## 🎯 В чём именно какая модель лучше

Обычные вопросы мы разделили по смыслу и по тому, какой код за ними стоит, и посмотрели, кто лидирует в каждой
группе. В скобках MRR@10. Giga-3B и Giga-10B это Giga-Embeddings-instruct-3B и -10B.

| | Группа вопросов | 🥇 1-е место | 🥈 2-е место |
|:-:|---|---|---|
| ⚙️ | Как работает какой-то код | Giga-3B (0.868) | Giga-10B (0.865) |
| 🔀 | Что происходит при определённом условии | Giga-3B (0.801) | Giga-10B (0.779) |
| 🗂 | Какие есть поля и параметры | Giga-10B (0.863) | Giga-3B (0.855) |
| 📍 | Где это реализовано | Giga-10B (0.887) | Giga-3B (0.872) |
| 💡 | Зачем сделано именно так | Giga-3B (0.868) | pplx-embed-v2-late-0.6b (0.855) |
| 🏷 | В вопросе назван класс или метод | Giga-3B (0.880) | Giga-10B (0.869) |
| 🔗 | Где используется класс или метод | bge-code-v1 (0.503) | Qwen3-Embedding-4B q4 (0.450) |
| 🇬🇧 | В нужном коде только английские комментарии | Giga-3B (0.843) | Giga-10B (0.816) |
| 🇷🇺 | В нужном коде есть русские комментарии | Giga-3B (0.852) | Giga-10B (0.850) |
| 👯 | В проекте есть почти копия нужного кода | F2LLM-v2-4B (0.805) | Giga-3B (0.788) |

Остальные места и все модели по каждой группе есть в [подробном отчёте](results/report.md).

| ⚡ | Приближённый индекс IVF_HNSW_PQ в LanceDB | по качеству не отличается от точного поиска | индекс можно смело использовать |
| 📋 | Вопросы-перечни вроде «напиши все классы безопасности и работы с БД» | в 30 кусков попадает 8–14% нужных файлов, в 90 кусков 25–39%, карточки файлов покрывают около 90% | векторный поиск тут не подходит, нужен каталог файлов |

| Шаг | Что делаем |
|:-:|---|
| 1️⃣ | Режем каждый файл на куски по синтаксису: один кусок это один класс, метод или функция. Кусок длиннее 2000 символов режем на окна по 1500 символов с перекрытием 300. |
| 2️⃣ | Составляем вопросы: 2000 обычных, где нельзя называть классы и методы, 204 с именами и 250 «где используется». |
| 3️⃣ | Каждая модель превращает в векторы все окна проекта и вопрос, ищем ближайшие окна, кусок получает оценку лучшего окна. |
| 4️⃣ | Считаем метрики внутри каждого языка и усредняем, проверяем значимость разницы между моделями. |
| 5️⃣ | Claude вслепую перепроверил 1038 спорных вопросов: исходная разметка подтвердилась в 98% случаев, места лидеров не поменялись. |
